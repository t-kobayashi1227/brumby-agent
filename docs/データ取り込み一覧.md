# データ取り込み一覧（段階2）

`docs/設計まとめ.md`「使用するデータ（37件）」を、どの順に、どうやってDBに入れるかの一覧です。取得先の詳しい調査は `docs/参考/公的データ調査_2026-10-23.md` にあります。

## 使い方

```
npm run ingest -- <ジョブ名>        # 取り込む（同じデータの古い行は入れ替わる）
npm run ingest -- <ジョブ名> refresh    # 保存済みのファイルを使わず、ダウンロードし直す
npm run ingest -- iryou date=2026-10-24   # オプションは「名前=値」で書く（PowerShell では「--名前」が npm に取られるため）
npm run ingest -- status            # データごとの件数と時点の一覧（段階2の完了条件）
```

- 元データは `data/raw/<フォルダ>/` に置きます（git には入りません）。自動でダウンロードできるものは、ジョブがここに保存します。
- 取り込みは1つのトランザクションで行います。途中で失敗したら全部取り消され、DBは取り込み前のままです。
- 結果は `ingest_logs` に、件数と時点は `datasets` に残ります。

## 段階3で使うときの注意（データの癖）

事実シートを作るとき（段階3）に知っておくことです。表の説明は `docs/DBの形.md` にあります。

**区域（zones）**

- 洪水（D31）：同じ地点が**複数の川の区域に入る**のが普通（例：新潟駅は阿賀野川・信濃川・小阿賀野川）。事実の値には一番深いもの（`attrs.浸水深ランク` が最大）を使い、川の名前を添える。区域は「川×浸水深×約1km四方の枠」でまとめ、さらに切れ端に分けて入れているので、同じ区域が何行にも分かれている（`label` と `attrs.河川名` で distinct を取る）。想定最大規模。輪郭は10mの精度で単純にしてある
- 津波（D34）：浸水深の区分の文字（例：`1m以上〜3m未満`）がそのまま `label`。新潟県の2017年版
- 土砂（D33）：`label` は「土砂災害特別警戒区域（土石流）」など。指定前（基礎調査の結果）の区域もある。出典の文言は A33 の決まった文言（`datasets.attribution`）を使う
- 盛土（D36）：**新潟市には大規模盛土造成地が無い**（新潟県のページで小林さんが確認）。新潟市の物件は「該当なし」と書く（「取得できず」ではない）
- 液状化（D35）：`label` は「液状化しやすい（三角州・海岸低地）」など。250m の区画
- 用途地域（D04）：`label` は全角の数字のまま（例：`第１種中高層住居専用地域`）。市街化調整区域など、用途地域の無い所は区域に入らない
- 災害は「区域外だから安全」と書かない（設計まとめ「災害情報の扱い」）

**施設（facilities）**

- `kind` は20種類。スーパー・ドラッグストアは OSM（D28）と大規模小売店舗一覧（D29。OSM に無い店だけ）の両方から入っている。数えるときは `dataset_id` を分けずに `kind` で数える
- 大規模小売店舗（D29）は種類を問わず全店。`attrs.店舗面積_㎡`・`attrs.主な小売店舗` がある
- 駅（D25）：`attrs.路線`、`attrs.乗降客数_2024`（53駅だけ。無い駅は「取得できず」）
- バス停（D27）：`attrs.事業者`、`attrs.系統`、`attrs.系統数`
- 医療（D30）：病院・診療所は `departments`（診療科の配列）がある。歯科・薬局は無い。住所から位置を出した行は `attrs.位置` が「住所から推定」
- OSM の名前の無い店（44店）は `name` が「（名前の無いスーパー）」など
- 区内の町の平均件数は `ward_facility_averages`（町の中心から1km以内。水面の町は除く）。施設を入れ直したら `npm run ingest -- ward-averages` で計算し直す

**町と統計（towns・area_stats）**

- 国勢調査（D05〜D08）：町は `area_key` が KEY_CODE（丁目の無い町は9桁、丁目は11桁）。`raw.段階` が「丁目のある町の合計」の行（9桁）もあり、丁目が秘匿のときに使える。秘匿（X）は `value` が null、該当なし（-）は 0。区は `area_level = '区'`・`area_key = '西区'`
- 町名別人口（D10）：`area_key` は「区:町丁名」（例：`北区:朝日町１丁目`。全角の数字）。国勢調査の町名（例：`関屋下川原町二丁目`）と書き方が違うので、照らし合わせるときに数字の書き方をそろえる。秘匿（x）は null。区の値は秘匿の町丁を除いた合計
- 将来人口（D11）：`population` に年ごとの総数・年齢区分（2020年は総数だけ）

**相場（transactions・land_prices）**

- 取引価格（D01）：町への対応（`town_key_code`）は付けていない。`ward` と `district_name`（丁目の無い町名）で照らし合わせる。戸建ては `type = '宅地(土地と建物)'`。築年数は取引の年 − `building_year`
- 地価（D02・D03）：`use_category`（住宅地・商業地など）で住宅地を選ぶ

**学区（school_zone_rules）**

- 住所との照らし合わせは `lib/facts/school-zones.ts` の `parseAddress` と `resolveZone`（テストあり）。決まらないときは候補が複数返る →「要確認」
- 地番の書き方が複雑で読み取れない行が158行ある

**買い手（reference_stats・assumptions）**

- 世帯年収の分布には「無回答」の行がある。必要年収以上の割合は、無回答を除いた残りで割り直す（小林さんのメモ）
- 中古戸建の世帯主の年齢は合計 95.2%（残りは無回答と思われる）
- 金利・頭金・返済負担率などは `assumptions`（適用開始日が今日以前で一番新しい行を使う）
