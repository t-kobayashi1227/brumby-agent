- ④を「戦略（Sonnet 5.5）→ 媒体（Haiku 5.5）→ 確認（Sonnet 5.5）」の3回の呼び出しで動かせるようにする。
- 今の形（7回の呼び出し）は消さずに残し、どちらでも動かせるようにする。画面とその API は今の形のまま使う（画面は段階2で切り替えると決めてから直す）。

範囲に入れないこと：画面の変更、7.1 の事実の追加、知識（knowledge/）、比べ方の決め事。

## 作業

### 1. DB（マイグレーション1本）

`supabase/migrations/<日時>_strategy_v3.sql`

| 表 | 変更 | 理由 |
| --- | --- | --- |
| strategy_runs | `pipeline text not null default '7回'`（'7回'・'3回'） | 今の画面は今の形の結果しか読めない。どちらの形の実行かを見分ける |
| strategy_runs | stage の選択肢に「戦略」を足す | 進み具合の表示 |
| agent_calls | agent の選択肢に「戦略」を足す | 新しい担当 |
| agent_calls | `effort text` を足す | medium と high を比べるため、呼び出しごとに残す |
| check_results | target の選択肢に「戦略」を足す。action の選択肢に「記録だけ」を足す | 戦略の文の場所を残す。禁止語は記録だけ |

check_results の action は、これから「点検が求める扱い」（作り直し・外す・記録だけ）を残す意味にする。作り直しはしないので、action が「作り直し」の行が、そのまま「作り直す原因」の一覧になる。今までの行（作り直しを止めて「なし」にしたもの）はそのまま残す。

### 2. モデルと料金（`lib/agents/cost.ts`）

- モデルごとの料金表にする。`claude-haiku-5-5`（入力 $0.10・出力 $0.50、10万トークンを超えると $0.50・$2.50）と `claude-sonnet-5-5`（入力 $2.00・出力 $10.00）。キャッシュの読み込み0.1倍・書き込み1.25倍は今のまま。
- `costUsd(usage, model)` にし、agent_calls に残す model と同じものを使う。
- 担当ごとのモデルと考える量を1か所にまとめる（戦略・確認は Sonnet、媒体は Haiku。今の形の7つは Haiku のまま）。

### 3. 呼び出し（`lib/agents/llm.ts`）

- `callModel` に model・effort・max_tokens を渡せるようにする。
- `messages.stream()` に今と同じ `output_config.format`（zodOutputFormat）と effort を渡し、`finalMessage()` の `parsed_output` を使う（SDK 0.131.0 で使えることを確かめ済み）。今の形の呼び出しもストリーミングにそろえる（答えは変わらない）。
- max_tokens は、戦略 64,000、確認 32,000、ほかは今の 16,000。
- 断られた・途中で止まった・JSONが読めないときの扱いは今のまま（失敗として記録）。

### 4. 答えの形（`lib/agents/schemas.ts`）

戦略の答え＝分析＋メインの答え。

```ts
strategySchema = z.object({
  analysis: z.array(z.object({
    kind: z.enum(["物件", "立地", "価格", "買い手", "組み合わせ", "その他の気づき"]),
    fact: z.string(),      // どの事実か
    meaning: z.string(),   // 買い手にとっての意味
    use: z.string(),       // 販売での使い方
    evidence, confidence,
  })),
  unknown: z.array(z.string()),
  ...mainSchema の項目（summary・targets・not_fit・appeals・price_view・concerns・direction。形は今のまま）
})
```

- メインの答えの形を変えないので、媒体担当と今のプログラムの点検（事実ID・取得できず・IDのない文を外す）はそのまま使える。
- strategy_runs.result は `{ pipeline: "3回", fact_sheet_id, 戦略: { analysis, unknown }, メイン, 媒体, 予算シミュレーション }` の形にする。

### 5. プログラムの点検（`lib/agents/checks.ts`）

- 文の一覧に、戦略の analysis（fact・meaning・use）を足す。IDのない分析は外す。
- 禁止語の点検を足す：「必ず」「最適」「人気の」「査定」「保証」「徒歩」。
  - 「徒歩○分」は、交通（T）の事実の値にある徒歩分と一致すれば通す。
  - 当たっても作り直さず、action「記録だけ」で残す。
  - 見る文は、戦略と媒体の答えのすべての文字列（text・reason・action・fact・meaning・use など）。
- 確認担当の where（例：analysis[2].meaning）を、戦略か媒体かに分ける（`splitWhere` に analysis を足す）。

### 6. 指示文（試しの指示文として `prompts/v3/` に置く）

| ファイル | 中身 |
| --- | --- |
| `prompts/v3/strategy.txt` | 戦略担当（第3版）。修正案6の形：役割と目的、良い答えの見本1つ（架空の物件）、本当に必要な決まり5つ、「事実→意味→使い方」で書くこと、組み合わせた見立て、その他の気づき。プログラムで点検する決まりは書かない |
| `prompts/v3/check.txt` | 確認担当。修正案5.2の案のとおり |

- 媒体は今の `prompts/common.txt`＋`prompts/media.txt` をそのまま使う。
- `prompts/` の正本（設計まとめと一字一句同じもの）は変えない。今のテスト（tests/prompts の確かめ）もそのまま通る。
- **戦略担当の指示文は、私が案を書き、了承をいただいてから使う**（CLAUDE.md の決まり）。確認担当は修正案5.2の案をそのまま使うので、修正案の了承をもって使う。

### 7. 流れ（`lib/agents/run-v3.ts` を新しく作る）

今の `run.ts` は今の形のまま残し、共通の部分（呼び出しの記録、点検の保存、進み具合、金額の計算、失敗したときの記録）を `run.ts` から切り出して両方で使う。

1. 戦略：事実シート全体を渡す
2. 媒体：P・B・C の事実と、戦略のメインの答えを渡す（今と同じ）
3. プログラムの点検 → 「外す」の文を取り除く
4. 確認：事実シート全体と、戦略・媒体の答えを渡す
5. 点検の結果をすべて check_results に残す（作り直しはしない）
6. 配分から金額を計算し、strategy_runs に結果と合計の費用を残す

### 8. 動かし方（`scripts/strategy.ts`）

- `npm run strategy -- <物件の番号> v3`：3回の形で動かす。`effort=high` を付けると戦略を high で動かす（比べるとき用）。
- 画面に出すのは、今と同じく段階・呼び出しの数・トークン数・費用・点検の件数だけ（テスト物件は秘密保持契約の対象のため、中身は出さない）。中身は DB で見る。
- 画面の「実行を開始」とその API は、今の形のまま。物件の画面は、`pipeline = '7回'` の最新の結果を出すようにする（3回の形の結果で画面が壊れないため。この1行の条件だけ直す）。

### 9. テスト（`tests/agents.test.ts` に足す）

- 料金：Sonnet 5.5 と Haiku 5.5 の計算、キャッシュの扱い
- 禁止語：当たる・当たらない、「徒歩○分」が交通の事実と一致すれば通す、action が「記録だけ」
- 点検：戦略の analysis の事実ID・取得できず・IDのない分析を外す
- where の分け方：analysis[…] は戦略、media[…] は媒体
- 戦略の答えの形：見本のJSONがスキーマを通る

### 10. 確かめ

1. `npx vitest run`、`npx tsc --noEmit`
2. マイグレーションを当てる
3. 物件1の事実シートを新しい相場で作り直して保存する（`npm run facts -- 1 save`）
4. `npm run strategy -- 1 v3` を1回動かし、記録（呼び出し3回、モデル、effort、費用、点検の結果）を確かめる。費用の目安は1回0.2〜0.3ドル
5. `npm run strategy -- 1`（今の形）も動き、画面に出ることを確かめる
