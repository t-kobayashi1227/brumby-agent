**「要確認」の列は未確認の項目**（`データ取得API一覧.md` が手元になく、公式マニュアルでの確認が必要なもの）。確認したら埋める。

## 3. 取れない・不足する項目（実測と既知）

| 項目 | 状況 | 影響 |
|---|---|---|
| 取引価格の位置 | 緯度経度はなく、地区名（町・大字）まで。名前で町丁目に結びつけると宅地の98.2%（実測） | 相場は地区単位。個別物件の近接成約例は出さない |
| 取引価格の鮮度 | 四半期ごと、約半年遅れ。売出価格ではない | ラベルで区別（D26） |
| 新潟市・長岡市の学区（XKT004/005） | データなし | 学区の訴求は出せない |
| 世帯年収 | 国勢調査にない | 画面から削る（7.1） |
| 共働き世帯 | 取り込む項目に入れていない | 20〜39歳の割合で代用（D21） |
| 住み替え元の築年 | 公開データにない | 住み替え層は仮説扱い |
| 販売期間・反響 | 公開データにない | 画面から削る |

## 4. 要確認の一覧（公式マニュアルで）

1. XKT系の個々のAPI IDと中身の対応（`データ取得API一覧.md` の対応には推定が含まれる）
2. 各APIのレート制限・取得件数の上限（取り込みの失敗の分類、D31に使う）
3. 各データの更新頻度と最新の公開年月
4. e-Stat・OSM・ジオコーディングの保存・出典・商用利用の条件
5. XPT001（取引価格のポイントAPI）の位置精度。PoCではXIT001を使い、XPT001は「代わりにできるか」の実測だけ

## 5. 取り込みの記録の場所
- 版ごとの件数・取得日・出典：`dataset_versions`
- 取り込みごとの結果・空欄率・失敗の種類：`ingest_logs`
- 物件ごと・APIごとの取得結果：`property_fetches`
