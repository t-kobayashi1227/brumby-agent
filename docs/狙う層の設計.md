# 狙う層の設計（修正しやすい形）

> **2026-10-12：この方式は使わなくなりました（設計書 D35）。** 狙う層は「採点ルール表」（ペルソナ A〜H × 5つの層 × 重み）で決めます。
> 計算は `lib/scoring/`、設定は `personas`・`scoring_rules` などの表（`docs/database-guide.md` の 7.5）、画面は `/rules`。
> この文書は、前の分析の結果を読むための記録として残しています。

2026-10-06 の決定（D21・D22）にもとづく叩き台。**候補・指標・基準値・点数はすべてデータ**で、コードには書かない。動かしてから `/rules` で直す前提。

## 1. 直しやすさの方針

| 直したいこと | 直す場所 | コードの変更 |
|---|---|---|
| 候補を足す・消す・名前を変える | `target_candidates` の行 | 不要 |
| 候補ごとに見る指標を変える | `rules`（kind=`target_score`）の行 | 不要 |
| 基準値（市平均＋何ポイント）を変える | 同上の `condition.delta` | 不要 |
| 指標ごとの重み（1点→2点）を変える | 同上の `effect.score` | 不要 |
| 点の付け方を個数方式から差の大きさに変える | 同じ指標のルールを段階で複数行にする（4章） | 不要 |
| 新しい指標を足す | 集計の部品（`lib/analyzers/`）にカードを1種足す | 必要（カードの追加のみ） |
| 同点・全員低得点のときの扱い | `analysis_runs.params` の `min_top_score`、`tie_margin` | 不要 |

## 2. 追加するテーブル

```sql
create table target_candidates (
  id          text primary key,        -- family | dual_income | replacement | senior | land_buyer
  label       text not null,           -- 画面とAIに出す名前
  description text,                    -- 人物像の短い説明（AIに渡す材料）
  property_types text[] not null,      -- この候補を評価する物件種別。空配列なら全種別
  sort_order  smallint not null default 0,
  enabled     boolean not null default true
);
```

`rules` 側は、条件に「物件種別の絞り込み」（`when`）を任意で持てるようにする。

```json
{
  "id": "R-T01",
  "kind": "target_score",
  "condition": {"fact": "target.age_30_49_ratio", "op": ">", "than": "comparison", "delta": 0.0,
                "when": {"property_type": ["新築戸建", "中古戸建"]}},
  "effect": {"candidate": "family", "score": 1},
  "note": "30〜49歳の割合が市の平均より高いエリアは、子育て世帯の需要が見込める"
}
```

## 3. 候補と初期ルール（叩き台）

使う指標は、すでにあるカード（`database-guide.md` のkey一覧）を優先する。**新規カードは2つだけ**（太字）。

| 候補 | 対象の物件種別 | 指標（カードkey）→ 1点の条件 |
|---|---|---|
| **family**：30〜40代の子育てファミリー | 新築戸建・中古戸建 | `target.age_30_49_ratio` が市平均を上回る／`target.households_with_under18_ratio` が上回る／`target.couple_children_ratio` が上回る／`target.private_rented_ratio` が上回る（賃貸からの住み替え元がいる） |
| **dual_income**：20〜30代の共働き夫婦 | 新築戸建・中古戸建 | **`target.age_20_39_ratio`** が市平均を上回る／`target.private_rented_ratio` が上回る／`facility.station_nearest` が800m以内（直線） |
| **replacement**：近隣からの住み替え層 | 新築戸建・中古戸建 | `target.detached_ratio` が市平均を上回る／**`target.age_65plus_ratio`** が上回る（築古の目安）／`future.population_change` が -5% より良い |
| **senior**：子育て後のコンパクトな住み替え | 新築戸建・中古戸建（平屋・小さめ）、土地 | `target.age_65plus_ratio` が市平均を上回る／`facility.station_nearest` が1,000m以内／`facility.nursery_count` ではなく `target.couple_children_ratio` が下回る（子育て終了の目安） |
| **land_buyer**：土地購入の注文住宅層 | 土地 | `target.age_30_49_ratio` が市平均を上回る／`market.unit_price_median` が物件の㎡単価以上（相場より割安）／`area.zoning` が住居系 |

注意点：
- **共働きは年齢帯で代用**（D21）。画面とAIの文では「共働き」と断定せず、「20〜39歳の割合が高い（共働き夫婦が多い可能性）」と書かせる。
- **replacement は根拠が弱い**。公開データでは住み替え元の築年が分からない。点が付いても「仮説」のラベルを必ず付ける（`decision.target_rank` の `basis` に `confidence: "low"` を入れる）。
- `senior` の指標3つ目は代用。聞き取りで外してよい。
- 閾値（800m、1,000m、-5%）は仮の数字。BRUMBY様に聞いてから決める。

## 4. 点の付け方：個数方式から差の大きさ方式への移行

最初は同じ指標につき1行（`delta: 0.0`、1点）。差の大きさで加点したくなったら、**同じ指標の行を足すだけ**で移れる。コードは変えない。

| 行 | condition | effect |
|---|---|---|
| R-T01a | `age_30_49_ratio > comparison + 0.00` | family +1 |
| R-T01b | `age_30_49_ratio > comparison + 0.05` | family +1（合計2点） |
| R-T01c | `age_30_49_ratio > comparison + 0.10` | family +1（合計3点） |

## 5. 順位付けの手順と、同点・低得点のとき

`lib/rules` が次の手順で判断カード `decision.target_rank` を作る（コードは候補の中身を知らない）。

1. `enabled` な候補のうち、物件種別が合うものだけを対象にする。
2. 対象の候補ごとに、`target_score` ルールを評価して点を足す（効いたルールのidを記録する）。
3. 点の高い順に並べる。
4. 次の2つに当てはまるときは、**順位を無理に決めない**。
   - 1位の点が `min_top_score` 未満（初期値2）→ 「エリアの特徴からは絞り込めない」の判断カード（`status=insufficient`）
   - 1位と2位の差が `tie_margin` 以内（初期値0）→ 同点として併記する
5. 指標が1つも取れない候補（`status` が `ok` でない）は、点の分母から外し、「判断できない」と明記する。

`decision.target_rank` の `basis` の形：

```json
{
  "ranking": [
    {"candidate": "family", "score": 4, "max": 4, "fired": ["R-T01", "R-T02", "R-T03"], "confidence": "normal"},
    {"candidate": "dual_income", "score": 2, "max": 3, "fired": ["R-T05"], "confidence": "normal"}
  ],
  "tied": false,
  "unresolved": false
}
```

`max`（満点）を持たせるのは、指標が取れなかった候補と点数を公平に比べるため。

## 6. AIに渡すもの

- 順位と、効いたルールの `note`（BRUMBY様の言葉）、その指標のカード番号
- 候補の `label` と `description`
- 「属性を断定しない」「共働き・住み替え元は仮説と書く」の指示

AIは順位を変えない。人物像の言葉づくりと、理由の説明だけを書く。

## 7. 実装の順序（この設計から作るもの）

1. マイグレーション：`target_candidates`、`properties` の追加列（D15）、`narratives` の計測列（D17）、`evaluations`（D18）
2. カードを2つ追加：`target.age_20_39_ratio`、`target.age_65plus_ratio`（既存の `target.age_30_49_ratio` と同じ部品の年齢帯違い）
3. `lib/rules`：`target_score` の評価と順位付け（5章）
4. `seed-rules` に上の初期ルールを追加（既存の番号は上書きしない）
5. `/rules` 画面：`target_candidates` の編集と、`when`（物件種別）の選択を足す
