作成日：2026年10月31日  
対象：brumby-agent／Supabase brumby-poc  
確認基準コミット：`21943e52f947f5ac604c63f9ced5e69fbcc08c1e`

## 1 目的と確認範囲

販売戦略AIへ渡す事実シートについて、数値の誤りを直し、統計の対象地域・推計条件・位置精度を正しく伝える。優先するのは中古戸建購入者の年齢構成と、残差を無回答とみなす処理の修正である。

調査対象は、GitHubの取得・集計・出力実装、Supabaseの保存データ、登録4物件の最新事実シート（ID 29・31・32・33）。購入者統計の一部を国土交通省の原表と照合し、施設件数・ローン計算・災害区域の一部を再計算した。全統計・全施設・ハザード原図の全件検証ではない。

実装着手時は最新コードとの差分を確認する。本書の「確認済み」は調査時点の状態を示す。

## 3 個別の修正内容

### F01 中古戸建購入者の年齢構成

**確認結果**  
`reference_stats` の中古戸建購入者・60歳以上は14.6%。国土交通省「令和7年度住宅市場動向調査」報告書p.39では、60代11.9%と70歳以上7.5%の合計が19.4%。保存済み4物件の事実シートにも14.6%が反映されている。

| 年代 | 現在のDB | 修正後 |
|---|---:|---:|
| 30歳未満 | 5.5% | 5.5% |
| 30代 | 22.9% | 22.9% |
| 40代 | 26.5% | 26.5% |
| 50代 | 25.7% | 25.7% |
| 60歳以上 | 14.6% | 19.4% |
| 合計 | 95.2% | 100.0% |

**対象**  
DB：`reference_stats`。調査時の対象行IDは23。更新対象はIDだけに依存せず、`dataset_id=B02`、`category=世帯主の年齢`、`segment=中古戸建を買った世帯`、`item=60歳以上`で確認する。取込元は `data/raw/buyers/買い手の統計.csv`、取込処理は `scripts/ingest/jobs/buyers.ts`。

**修正方法**  
取込元とDBの両方を修正し、再取込で誤値が復活しないようにする。出典に「p.39、60代11.9%＋70歳以上7.5%」を残す。別の地域区分や住宅区分の行は変更しない。

**完了条件**  
対象行が19.4%、当該年代分布の合計が100.0%となり、再生成した事実シートにも19.4%が表示される。

### F02 残差を無回答とみなす処理

**確認結果**  
`lib/facts/build.ts` の `withRemainder` は、100%から登録値の合計を引いた残りを「無回答など」として追加する。F01の転記誤りにより、4物件すべてで「無回答など4.8%」という原表に基づかない値が生成された。

**修正方法**  
無回答は原表に明記された値だけを保存・出力する。合計不足を自動的に無回答へ変換しない。合計不一致は「内訳の合計に差があるため要確認」とする。丸め誤差、カテゴリの抜け、転記誤りを区別する。複数回答の統計には100%合計チェックを適用しない。

**対象**  
`lib/facts/build.ts` の `withRemainder` と `buyerFacts`、`scripts/ingest/jobs/buyers.ts`、`tests/facts.test.ts`。必要に応じて取込時の検証を追加する。

**完了条件**  
修正後の中古戸建分布から「無回答など4.8%」が消える。意図的に合計95.2%の入力を与えても、4.8%を無回答として捏造しない。原表に明示された無回答は保持する。

### F03 統計の対象地域

**確認結果**  
`buyerFacts` は年収分布の出典と項目名に一律「全国」を付ける。中古住宅は全国調査だが、分譲住宅は三大都市圏が対象。新築の年収分布では表示が不正確になる。調査時点の4物件は中古のため、この新築向けの誤表示は保存済み4物件で実証したものではなく、実装から確認した問題である。

**修正方法**  
統計単位で対象地域を保持する。同じ報告書でも表・指標により集計対象が異なるため、データセット全体に一つの地域を付けるだけでは不十分。年収分布、年代、住宅を探した方法それぞれに対象地域と出典ページを持たせる。既存の `note` にある地域情報も原表と照合して整理する。

推奨する情報は「調査年度」「対象地域」「住宅区分」「設問・表・ページ」「複数回答かどうか」。年収分布の表示は中古なら全国、新築分譲なら三大都市圏とする。全国値や三大都市圏値を新潟の購入者割合と表現しない。

**対象**  
`reference_stats`、取込元CSV、`scripts/ingest/jobs/buyers.ts`、`lib/facts/collect.ts` の `collectBuyers`、`lib/facts/build.ts` の `BuyersInput` と `buyerFacts`。列追加が必要なら最新スキーマを確認して設計する。

**完了条件**  
新築の事実シートに「全国の分譲戸建購入者の年収分布」が出ない。中古・新築の両方をテストし、AIへ渡すJSONにも対象地域が残る。

### F04 施設位置の推定情報

**確認結果**  
医療施設3,308件中211件は住所から位置を補完している。DBの `attrs` には推定位置の情報があるが、`collectNearby` はこれを取得せず、事実シートに精度が伝わらない。4物件周辺の件数を再集計するとDBとは一致したが、それは施設の実位置が正しいことを意味しない。

**修正方法**  
施設ごとの位置取得方法を集計結果まで引き継ぐ。住所検索による推定、他データの同一施設からの補完、元データ座標を区別する。「元データ座標」も現地確認済みとは表現しない。距離には「直線・位置推定」を付け、件数には推定位置を含む件数を併記する。1km境界付近の推定施設は地図で確認する対象にする。根拠のない一律の誤差幅は付けない。

表示例：「スーパー3件（うち位置推定1件）。最寄り約600m、直線距離、位置推定を含む」

**対象**  
`lib/facts/collect.ts` の `collectNearby`、`lib/facts/build.ts` の `NearbyKindInput` と `nearbyFact`、必要に応じて `lib/facts/format.ts`。取込時の情報は `scripts/ingest/jobs/iryou.ts` と `d29-large-stores.ts` を参照する。

**完了条件**  
DBに推定情報がある施設では、出力にも同情報が残る。推定施設を含むことを表示しても、距離・件数の算式を意図せず変更しない。

### F05 洪水の深さと河川名

**確認結果**  
物件1では信濃川・阿賀野川・小阿賀野川が0.5〜3.0m未満、鳥屋野潟が0〜0.5m未満。現在は最大深さに全河川名を添えるため、各河川で同じ深さと読めてしまう。最大深さ自体はDBと一致する。

**修正方法**  
最初に最大深さを示し、該当河川だけを列挙する。必要なら河川ごとの内訳も渡す。同じ河川の複数区域に当たる場合は、河川ごとに最大値を取ってからまとめる。

出力例：「最大0.5〜3.0m未満（信濃川・阿賀野川・小阿賀野川）。鳥屋野潟は0〜0.5m未満」

**対象**  
`lib/facts/build.ts` の `hazardFacts`、`tests/facts.test.ts`。

**完了条件**  
異なる深さの河川が混在しても対応関係を失わない。同じ深さだけの場合と、該当区域がない場合も確認する。今回確認した物件1・3を回帰確認に使用する。

補足：洪水・津波の取込では輪郭を単純化している。境界付近の判定精度や原図との一致は今回の全件検証対象外。「区域の外」を安全保証へ言い換えない。

## 4 精度と解釈の改善

### F06 古い施設情報と営業状況

放課後児童クラブは2017年、公園は2019年、バス停は2022年など、データ時点が異なる。古いという理由だけで誤りと断定せず、データ基準日と取得日を分け、営業・存続・路線の現況が未確認であることを残す。

更新優先順位は販売上の影響が大きいスーパー、学校・保育施設、医療、交通を中心に決める。まず最新の一次情報があるか確認し、移転・閉鎖・名称変更を突き合わせる。施設分類についても、DB上「診療所」に歯科のみの施設が含まれる例を確認したが、原データの区分を誤りと断定せず、一般医療へのアクセスとして誤解されない表示を検討する。

完了条件：取得日が新しいだけで施設情報まで最新と表示しない。更新対象と未確認項目を追跡できる。

### F07 相場の比較条件

物件1では区の一般比較が2022〜2026年・83件、広さの近い比較が2015〜2026年・23件。現行の条件に従った結果だが、期間が異なる比較を同じ精度で扱わない。

取引期間、件数、築年数帯、土地・建物面積条件をAIに保持させる。「土地と建物の総額を延床面積で割った坪単価」であることを明示し、建物単体の価格と混同させない。相場比だけで割高・割安や適正売価を断定しない。価格時点の補正や地域細分化は今回の誤り修正とは別の改善として検討する。

対象：`collectMarket`、`selectMarket`、`marketFacts`、`similarFact` と、それらを解釈するAI指示文。

完了条件：新旧の取引が混在する場合に期間と限界が読み取れ、事実シートの条件が戦略生成時に失われない。

### F08 計算値と参考統計

ローンの計算式は確認例で一致したが、採用金利の現時点の妥当性は未検証。金利は金融機関・商品・適用条件・基準日を紐付ける。頭金10%、返済負担率25%、返済期間35年などは計算前提として表示する。「必要年収」は審査通過を保証する値ではなく、設定した返済負担率から逆算した目安とする。

年収以上の世帯割合は、無回答を除外して再集計し、所得階級内が均等に分布すると仮定した推計。この条件を出力にも残す。成約確率や新潟の購入可能人口比とは区別する。

SNS利用率、新聞の重要度、住宅を探した方法は、広告の成約率・費用対効果・最適な配分率ではない。媒体選択の参考には使えるが、予算配分へ変換する部分はPoC上の仮説として別管理する。

対象：`assumptions`、`lib/calc/loan.ts`、`buyerFacts`、媒体提案のAI指示文。完了条件は、計算前提・統計値・配分の仮説が区別できること。

## 5 実装と検証の順序

1. 最新コード・DBを再確認し、修正対象の値、元CSV、既存事実シートIDを記録する。
2. F01の取込元とDBを直し、F02の残差処理を修正する。
3. F03の対象地域、F04の位置精度、F05の河川別深さを出力に反映する。
4. F06〜F08の注意事項を、事実シートとAI指示文の両方へ反映する。
5. 年代分布、残差、対象地域、推定位置、河川別深さの回帰テストを実行する。
6. 既存4物件の事実シートを新規生成し、修正前後の差分を確認する。既存の保存済みJSONはコード修正だけでは更新されない。
7. 販売戦略も更新する場合は、新しい事実シートを参照して再生成する。旧レポートは履歴として区別する。

再生成には既存の `npm run facts -- <物件番号>` を利用できる。番号の指定形式は実行前にCLI実装で確認する。戦略の再生成はAI呼び出しを伴うため、事実シートの検証後に行う。
