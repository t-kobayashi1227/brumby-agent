# 販売戦略エージェント 設計まとめ（①〜⑤）

Oct 24, 2026 · @小林

## 全体像

この資料は、①〜⑤の資料と2026-10-24までの決定を、実装の前に1つにまとめたものです。元の資料と食い違うときは、この資料を正とします。

流れ: ①入力 → ②収集 → ③事実シート → ④エージェント（AIを使うのはここだけ） → ⑤画面

- **方針:** 情報の取得と計算はシステムが行い、エージェントは渡された事実だけで判断します。同じ物件には毎回同じ事実が渡るので、根拠の数字が確かになります。
- **根拠:** 画面に出す文にはすべて事実IDを付け、IDから項目・値・出典・時点を引いて表示します。
- **対象範囲:** PoCは新潟市の戸建て（新築・中古）です。最終的には新潟県に広げますが、同じDB保存の仕組みで対応します。
- **AIモデル:** 戦略担当と確認担当は claude-sonnet-5-5、媒体担当は claude-haiku-5-5 です（2026-10-31 決定。経緯は `docs/履歴/戦略の質を上げる修正案.md`）。1物件あたりの費用の上限はPoCでは設けません。
- **保存:** 事実シート、各エージェントの入力と出力、点検の結果を、物件ごとにDBに保存します。後から「なぜこの戦略になったか」をたどれるようにするためです。

## ①物件情報の入力

クライアントが入力するのは、物件資料にある13項目と、任意の競合物件・広告予算の総額です。周辺情報・学区・相場はシステムが取得します。

### 入力項目

| 項目 | 入力の形 | 必須 | 使い道 |

### 入力画面の動き

- **交通:** 1つ目を入力すると2つ目の欄が使えます。物件資料の「新潟交通バス「○○」停 徒歩3分」をそのまま移せる形にします。
- **リフォーム:** 「あり」を選ぶと、年と箇所の欄が出ます。箇所はキッチン・浴室・トイレ・洗面・内装全面・内装一部・外壁・屋根・その他から複数選びます（「内装一部」は10-25追加。クロスの張り替えだけ、など部分的な内装リフォームのため）。
- **位置の確認:** 住所を入れると地図にピンが立ち、クライアントが動かして直せます。住所によっては町丁目の中心に置かれて数百mずれるためです。確定した位置が周辺情報・学区・相場のもとになります。

### 項目ごとの扱い

- **間取りとS（納戸）:** 「4LDK+S」は「居室4、納戸1」として渡します。家族の人数の判断では「もう1部屋使える」として扱い、広告では居室とは書きません。
- **階数:** 「平屋」を含むので、平屋の欄は別に作りません。スキップフロアや一部2階建ては、特徴ピックアップからエージェントが読み取ります。
- **特徴ピックアップ:** 入力された文字をそのままエージェントに渡します。画面の根拠は「シャッター車庫あり（物件資料）」とし、「雪国で便利」などの解釈はエージェントの見立てとして分けて表示します。周辺の文言（「スーパー徒歩10分以内」など）がシステムのデータと食い違うときは、データを根拠に使います。
- **競合物件:** 入力があれば、区平均に加えて競合とも比べます。住所から位置を出し、物件との直線距離も事実にします。空欄なら区平均とだけ比べます。
- **広告予算の総額:** AIは媒体ごとの配分（%）だけを出します。総額が入力されていれば、システムが配分から金額を計算して表示します。

## ②物件周りの情報の収集

物件周りの情報は、システムが公的データとOpenStreetMapから集めます。データはすべて事前にDBへ保存し、物件ごとに外部と通信するのは、住所から緯度経度を出すとき（国土地理院 住所検索）だけです。

### 収集の流れ

1. **緯度経度を出す:** ①の住所から緯度経度を出し、地図のピンでクライアントに確認してもらいます。
2. **周りの施設を探す:** 1km以内の件数と最寄り、3km以内の最寄りを出します。
3. **区域を判定する:** 学区・用途地域・ハザードの区域のどこに入るかを判定します。学区は住所で市の通学区域一覧と照合して確定します。
4. **町の統計を引く:** 区×築年数の戸建ての相場（延床の坪単価）、年齢構成、世帯構成、持ち家率を出します。町の統計は区平均と並べます。
5. **ローンを計算する:** 価格から月々の返済額と必要年収、必要年収以上の世帯の割合を計算します。
6. **事実をまとめる:** すべてを③の事実シートにします。取れなかった項目は「取得できず」と書きます。

### 範囲と距離

- **徒歩圏:** 1km以内の件数と、最寄りまでの距離です。
- **車圏:** 3km以内の最寄りです。無ければ「3km以内になし」と書きます。
- **距離の種類:** 直線距離です。画面と事実に「直線」と書き、徒歩分には直しません。
- **広告の徒歩分:** ①で入力した徒歩分を使います。公正競争規約では道路距離で分速80mのため、直線距離からは出しません。
- **将来:** 県に広げるとき、道のり距離の計算（OSRM）を検討します。

### 災害情報の扱い

災害情報は「確認事項」として、良い悪いを付けずに事実だけを出します。洪水・津波の想定浸水深、土砂の区域、液状化の傾向、盛土を、データ名と年を添えて示します。内水はデータが無いため扱いません。「区域外だから安全」とは書かず、安全を訴求点にもしません。

### 買い手・ローンの前提

| データ | 提供元 | 時点 | 使い方 |
| --- | --- | --- | --- |
| フラット35利用者調査 | 住宅金融支援機構 | 2025年度（2026-07公表） | 頭金・返済負担率の実績 |
| 住宅市場動向調査 | 国土交通省 | 令和7年度（2026-07公表） | 中古戸建を買った世帯の年収分布・年代、情報収集の仕方 |
| 民間住宅ローンの実態に関する調査 | 国土交通省 | 令和7年度（2026-03） | 返済負担率の上限・完済年齢 |
| 変動金利 | 各銀行の公表金利 | 2026-10 | 基本の金利 |
| フラット35の金利 | 住宅金融支援機構 | 2026-10 | 慎重な場合の金利 |
| 情報通信メディアの利用時間と情報行動に関する調査 | 総務省 | 令和7年度（2026-06掲載） | 年代別のSNS利用率、テレビ・新聞・ネットの重要度 |

- **計算式:** 借入額＝価格×0.9（頭金10%）。月々の返済額＝借入額×r÷（1−（1＋r）の−n乗）、r＝年利÷12、n＝420回（35年）。必要年収＝月々の返済額×12÷0.25（返済負担率25%）。
- **金利:** 変動1.3%（基本）と全期間固定3.83%（慎重）の2通りで計算します。
- **返済期間:** 35年です。完済が80歳を超える場合は短くします。候補ごとの代表年齢を、若い夫婦30歳、小中学生のいる家族38歳、50代の住み替え55歳、60歳以上65歳、単身35歳、親と同居40歳とし、候補ごとに返済期間と必要年収を計算します（10-24仮決め）。返済期間が同じ候補は数字も同じなので、事実では1行にまとめて候補名を並べます（10-30）。
- **住み替えの頭金:** 50代の住み替え・60歳以上は、今の家を売ったお金を頭金にするのが普通なので、頭金10%の返済に加えて、二次取得者の自己資金比率を頭金にした返済も出します。中古は49.2%（既存戸建）、新築は58.3%（分譲戸建）で、住宅市場動向調査 令和7年度 p.49（三大都市圏）の値です。前提値の表に「住み替えの頭金の割合（中古）」「（新築）」として置き、使う候補は `target_candidates.uses_resale_down_payment` で決めます（10-30）。ただし比率は平均の価格（中古2,486万円・新築5,887万円）の家を買った人の値なので、高い物件にそのまま掛けると頭金が実際の平均より大きくなり、買いやすく見えすぎます。そのため頭金は「価格×比率」と「平均の自己資金の金額」（中古1,223万円・新築3,434万円。同じく p.49・三大都市圏、前提値の表の「住み替えの頭金の金額（中古）」「（新築）」）の小さいほうにし、項目名にどちらを使ったか（「平均の自己資金比率」「平均の自己資金」）を書きます。出典には「三大都市圏」と書きます（10-31）。
- **返済負担率の書き方:** 25%は無理のない目安で、審査の上限ではありません。AIが「この年収がないと借りられない」と言い切らないよう、ローン計算の出典に「返済負担率25%（無理のない目安。審査の上限ではない）」と書きます（10-31）。
- **必要年収以上の割合:** 新しく年収データは集めず、住宅市場動向調査の年収分布から、システムが計算します。中古は「中古戸建を買った世帯」、新築は「分譲戸建を買った世帯」の分布を使います（10-24仮決め）。
- **前提値の表:** 金利などの前提と根拠を、項目・値・根拠・時点・適用開始日の形でDBに保存します。金利は月1回、頭金・返済負担率は年1回（7月）、担当者が新しい行を追加します。事実シートにはどの前提値で計算したかを記録します。

### 更新と取れないとき

- **月次:** 金利、OpenStreetMap
- **四半期:** 取引価格・成約価格
- **年次:** 地価、国土数値情報、新潟市・新潟県のデータ、医療情報ネット、通学区域一覧、買い手・媒体の統計
- **公表時:** 国勢調査（2025年調査の小地域集計が出たら入れ替え）
- **位置が出ない:** 地図のピンをクライアントに動かしてもらいます。
- **相場の件数:** 町だけでは取引が少ないため、相場は区×築年数で出します（10-25 小林さんと決定）。築年数帯は築0〜1年・2〜9年・10〜19年・20〜29年・30〜39年・40〜49年・50年以上です。直近5年（取り込んだ最新の年から数える）で20件以上あれば直近5年、足りなければ取り込んだすべての年（2015〜）を使い、20件に足りなくてもそのまま出します。帯は広げません。件数は事実に書きます（10-28 小林さんと決定。詳しくは `docs/履歴/相場の出し方変更.md`）。
- **駅の乗降客数:** 乗降客数が0の駅は「公表なし」、駅別乗降客数（S12）に無い駅は「取得できず」とします（10-25 小林さんと決定、10-30 「データなし」から変更）。
- **学区が境界にかかる:** 状態を「要確認」にします。
- **そのほか取れない項目:** 「取得できず」と書いて渡し、エージェントには推測で埋めないように指示します。

## ③事実シート

事実シートは、1物件についてシステムが集めた事実の一覧です。エージェントにはこれだけを渡し、エージェントは事実IDを引用して戦略を書きます。入力したデータとシステムで取得したデータは、すべて事実シートに入れます。

### 事実1件の形

| 項目 | 内容 | 例 |
| --- | --- | --- |
| id | 事実の番号。エージェントが根拠として引用する | L-01 |
| 項目 | 何の事実か | 最寄りのスーパー |
| 値 | 事実そのもの | 直線650m |
| 比較 | 区平均など、比べる対象があるときの値 | 1km以内 2件 |
| 出典 | どのデータから取ったか | OpenStreetMap |
| 時点 | データの年月 | 2026-10 |
| 状態 | 取得できたかどうか | 取得／取得できず／要確認 |

計算（距離、件数、割合、返済額、相場比）はすべてシステムが済ませ、結果だけを「値」に入れます。比較の相手は区平均です。

### 事実IDの分類

IDは「英字1文字＋番号」です。分類から、どのエージェントに渡すかが決まります。

| M | 相場 | 区×築年数の延床の坪単価の相場、相場比、相場の取引の延床・土地面積、広さの近い取引の相場、公示地 | ②のNo.1〜3 |
| R | 規制 | 用途地域 | ②のNo.4 |

| S | 学区 | 小学校区、中学校区 | ②のNo.12〜14 |

### 周りの施設（L）の渡し方

最寄り1件だけでは、エリアの暮らしやすさが伝わりません。そこで、施設の種類ごとに次の4つを事実として渡します（10-24追加）。

- **1km以内の件数:** 徒歩圏にいくつあるかです。
- **区内の町の平均件数:** 同じ区の町ごとに、町の中心から1km以内の件数を事前に計算し、その平均を「比較」に入れます。多いか少ないかをエージェントが判断できます。
- **1km以内の一覧:** 名前と直線距離を近い順に最大5件渡します。大きな店や病院の名前は訴求に使えます。
- **3km以内の最寄り:** 1km以内に無い種類だけ、車で行ける範囲の最寄りを渡します。無ければ「3km以内になし」です。

種類は、小学校・中学校、保育園・地域型保育・幼稚園・こども園、放課後児童クラブ、公園、図書館、役所、スーパー、ドラッグストア、コンビニ、大規模小売店舗、病院、診療所、歯科、薬局です。駅とバス停は交通（T）の事実として、最寄りと1km以内のバス停の数を渡します。バス停は事業者ごとに点があるので、同じ名前の点は1つの停留所として数え、最寄りバス停には系統数の合計と事業者名を添えます（2026-10-30）。医療は、加えて診療科ごと（内科・小児科・外科・整形外科・産婦人科など）の1km以内の一覧と3km以内の最寄りを、区の町の平均と並べて渡します（区の平均は10-30から）。

## ④戦略の作成

③の事実シートを受け取った3つのAIエージェント（戦略・媒体・確認）が、販売戦略を作ります。各エージェントの指示文はこの資料の「エージェントの指示文」にあります。

以前は、物件・立地・価格・買い手の4つの分析エージェントとメインに分けた7回の呼び出しでした。担当を分けると、違う分類の事実を組み合わせた見立て（例：駅の近さ × 医療施設の多さ × 部屋数 → 二世帯）が出ず、メインも担当の結論をまとめるだけになったため、事実シート全体を1体の戦略担当が読む形にしました（2026-10-31 決定。経緯は `docs/履歴/戦略の質を上げる修正案.md`）。7回の形の記録はDBに残っています。

### 共通のルール

- **事実の数字と名前だけを使う:** 数字・施設名・店名・学校名・駅名・地名・統計の値は、事実シートからだけ使います。「取得できず」の事実は推測で埋めず、根拠にもしません。
- **見立ては自由に考える:** 事実を、買い手にとっての意味と販売での使い方まで考えます。そのときは不動産の一般的な知識を使ってよいです。
- **判断には必ず事実IDを付ける:** IDのない文は画面に出しません。
- **計算しない:** 距離・相場比・返済額・広告費の金額はシステムが計算済みです。エージェントが返す数字は媒体の配分（%）だけです。
- **約束しない:** 価格や売れることを約束しません。「必ず」「最適」「人気の」「査定」「保証」は使いません。
- **決まった形のJSONで返す:** ⑤の画面はこのJSONをそのまま表示に使います。

### エージェントと渡す事実

| 順 | エージェント | モデル | 役割 | 渡す事実 | 渡す答え | 結果 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 戦略 | claude-sonnet-5-5 | 事実を分析し、戦略を決める | すべて | ― | 分析（事実・買い手にとっての意味・販売での使い方）・総合評価・ターゲット・訴求・価格コメント・懸念点と対策・方向性 |
| 2 | 媒体 | claude-haiku-5-5 | ターゲットに届く媒体と配分 | P・B・C | 戦略の答え（分析を除く） | 推奨媒体・目的・想定ターゲット・配分 |
| 3 | 確認 | claude-sonnet-5-5 | 画面に出す前の点検 | すべて | 戦略と媒体の答え | 問題のある文 |

Lは③の「周りの施設（L）の渡し方」のとおり、種類ごとの件数・区内の町の平均・一覧・3km以内の最寄りを渡します。競合の入力がない物件では、Kは空のまま渡します。

- **確認を分ける理由:** 自分の文を自分で点検すると見落としやすいためです。戦略担当と同じモデルにして、点検する側が見立てを読み違えないようにします。
- **媒体を分ける理由:** 統計を見て配分を決める作業で、組み合わせた見立ては要らないためです。
- **考える量（effort）:** 戦略と確認は medium で始めます。戦略は分析と戦略を1回で作るので出力が大きく、ストリーミングで受け取り、max_tokens を 64,000 にします。

### 処理の流れ

1. 戦略担当が事実シート全体を受け取り、分析と戦略を1回で作ります。
2. 媒体担当が戦略のターゲットを受け取り、媒体と配分を決めます。
3. 点検は、まずプログラムで形を点検し（IDのない文はここで外す）、次に確認担当が中身を点検します。
4. **PoCでは作り直しをしません**（費用と時間のため。2026-10-30 決定）。見つかった問題は、点検が求める扱い（作り直し・外す・記録だけ）のまま check_results に残し、作り直しを入れるかは記録がたまってから決めます。
5. システムが配分から金額（①の総額、10万・20万・30万円）を計算し、⑤に渡します。

### ターゲット候補

候補は「若い夫婦」「小中学生のいる家族」「50代の住み替え」「60歳以上」「単身」「親と同居」の6つを基本とします。事実に支えがあれば、戦略担当が独自の候補を加えられます（sourceを「エージェント提案」にし、definitionに説明を書く）。上位は「買える見込み」「エリアとの合い方」「物件・立地が合うこと」がそろう候補から選び、数が多いという理由だけで第1にはしません。

PoCでは16件すべてを候補にし、本番ではBRUMBYと相談して使う媒体、費用の目安、地元の媒体を決めます。

### 確認のチェック項目

| 段階 | 点検すること | 点検が求める扱い |

| プログラム | IDのない文がないか | 外す（総合評価・価格の見方・方向性は1つしかないので作り直し） |

| プログラム | 「必ず」「最適」「人気の」「査定」「保証」「徒歩」がないか（「徒歩○分」は交通の事実と同じ分数なら通す） | 記録だけ（言葉の一致で見るので、問題のない文にも当たる） |
| AI | 数字が事実と合っているか | 作り直し |
| AI | 名前（施設・店・学校・駅・地名）が事実にあるか | 作り直し |

PoCでは作り直さないので、「作り直し」は check_results に残すだけです。外すのはIDのない文だけです。

## ⑤画面の表示

④のJSONを、クライアントがそのまま販売会議で使える1枚のレポートとして表示します。画面ではAIを動かさず、表示と金額の計算だけを行います。形は提案資料の「画面イメージ：販売戦略レポート」に合わせ、物件の見出しと「エリア分析・販売戦略・根拠データ」の3つのタブを持ちます。

画面は、サイドメニューの「物件一覧」と「設定」から開きます（2026-10-26 にデザイン案に合わせて変更）。

- **物件一覧（/properties）**：登録した物件ごとに、戦略の状態（未実行・実行中・完了・失敗）と第1ターゲットを出します。行を押すと、その物件のレポート（/strategy/[id]）を開きます。前の「販売戦略」の一覧（/strategy）は物件一覧にまとめ、開くと物件一覧に移ります。
- **設定（/settings）**：ローンの前提・ターゲット候補・媒体一覧を、DB の値のまま見られます（見るだけで、ここでは変えません）。

### 「販売戦略」タブの構成

| 順 | 表示ブロック | 最低限ほしい出力 | 元になる項目 | 表示のルール |
| --- | --- | --- | --- | --- |
| 0 | 物件の見出し | ― | 事実P・T | 所在地・価格・間取り・面積・駅徒歩・駐車 |
| 1 | 総合評価 | 総合評価 | summary | 2〜3文。点数やランクは付けない |
| 2 | 狙う層 | 第1〜第3ターゲットと各根拠 | targets | 順位の番号つき。エージェント提案の候補はdefinitionも添える。合わない層（not\_fit）は画面に出さずDBに残す（10-31決定）。confidenceは出さずDBに残す |
| 3 | 訴求ポイント | 主要訴求ポイントと優先順位 | appeals | rankの順に最大3つ |
| 4 | 価格の見方 | 価格戦略上のコメント | price\_view | 位置づけと売れやすさをラベルで出し、「周辺の取引と比べた目安であり、価格の査定や保証ではありません」を常に表示。エリア分析タブの先頭に出す（10-31決定） |
| 5 | 懸念点 | 販売上の懸念点 | concerns、媒体のcautions | 懸念点だけを出す（対策案は画面に出さない。10-26決定。AIの答えには action が残り、DBには保存する）。エリア分析タブの先頭に出す（10-31決定） |
| 6 | 販売の方向性 | 販売の方向性 | direction | 1〜2文。推奨販売時期はPoCでは出さない |
| 7 | 媒体と予算 | 推奨媒体・目的・想定ターゲット・参考予算配分 | media | 表と円グラフ。①の総額があれば金額も |
| 8 | 予算シミュレーション | 10万・20万・30万円の試算 | mediaのshare（システム計算） | 下の「予算シミュレーション」 |
| 9 | 出典の一覧 | ― | 使った事実 | 出典と時点の一覧は「根拠データ」タブに出す。決まったクレジット文言は全タブの下に、「／」でつないだ短い段落で常に出す。地図のクレジットは地図を出す物件の画面にあるので、レポートには出さない（10-31決定） |

画面の並び（10-31決定、提案資料の画面イメージに合わせる）：総合評価を一番上に置き、狙う層・訴求ポイント・媒体と予算を3列のカードで並べる。その下に販売の方向性を横幅いっぱいで置き、予算シミュレーションは初めは閉じておき、押すと開く。価格の見方と懸念点は、販売戦略タブを結論と打ち手だけにするため、エリア分析タブへ移す。各文の根拠は「根拠 n件」のチップで出し、押すと値・出典・時点が開く。

「エリア分析」タブには、先頭に価格の見方と懸念点を出し、続けて戦略担当の分析（事実・買い手にとっての意味・販売での使い方）を topic ごとに、組み合わせた見立てを先にして出します。「根拠データ」タブには事実シートをそのまま出します。各文はおよそ40字で、省略せず折り返して全文を出します。

### 予算シミュレーション

媒体の配分（%）に総額10万・20万・30万円を掛け、システムが媒体ごとの金額を計算します。下は配分が40・30・20・10%のときの例です。

| 媒体 | 配分 | 10万円 | 20万円 | 30万円 |
| --- | --- | --- | --- | --- |
| SUUMO | 40% | 4.0万円 | 8.0万円 | 12.0万円 |
| Instagram広告 | 30% | 3.0万円 | 6.0万円 | 9.0万円 |
| ポスティング | 20% | 2.0万円 | 4.0万円 | 6.0万円 |
| 現地看板・のぼり | 10% | 1.0万円 | 2.0万円 | 3.0万円 |

- **注記:** 表の上に「参考の配分を示した試算です。正式な費用・見積もりではありません。」と常に表示します。
- **端数:** 0.1万円単位で四捨五入し、合計がずれたときは配分の最も大きい媒体で調整します。
- **①の総額:** 入力があれば、その金額の列を一番左に足します。
- **最低料金:** 少ない予算では媒体の最低料金に届かないことがありますが、PoCでは考慮しません。

### 根拠と出典

- **文ごとの根拠:** 各文の下に「根拠：」として、IDから引いた事実の項目と値を小さく出します（例：根拠：0〜14歳の割合 15.8%（西区 11.9%））。押すと出典と時点も見えます。
- **出典の一覧:** 画面の一番下に、使った事実の出典と時点をまとめて出します。放課後児童クラブ（2017-03）など古いデータも時点をそのまま書きます。
- **取得できなかった項目:** 根拠データタブに「不明」と出します。
- **画面全体の注記:** 「このレポートは公開データと物件情報をもとにAIが作成した販売戦略の参考です。」をページの下に出します。

## エージェントの指示文

戦略と確認には自分の指示だけを、媒体には「共通の指示」と自分の指示をつなげて渡し、その後に事実と答え（JSON）を続けます。答えの形は structured outputs で決めます。指示文を変えるときは、小林さんの了承を得てから変えます。

### 共通の指示

```text
あなたは新潟市の戸建ての販売を支えるチームの一員です。次のルールを必ず守ってください。

1. 渡された事実だけを使う。一般知識や推測で、数字や施設名を作らない。
2. 状態が「取得できず」の事実と、渡されていない事実は使わず、unknown に書く。
3. 判断の文には必ず、元にした事実IDを evidence に入れる（例："L-04"）。IDを付けられない判断は書かない。
4. 計算しない。距離・件数・相場比・返済額・割合は、事実の値をそのまま使う。
5. 言い切らない。「〜に向く」「〜の可能性が高い」と書き、「必ず」「最適」「人気の」は使わない。価格について「査定」「保証」「この価格で売れる」は使わない。
6. 距離は「直線○m」と書き、「徒歩○分」に言い換えない（入力された駅・バス停の徒歩分はそのまま使ってよい）。
7. 災害の事実は値をそのまま書き、「安全」「心配ない」と書かない。
8. 文は1文およそ40字、営業担当者がそのまま読める普通の言葉で書く。
9. confidence は、複数の事実がそろうとき「高」、1つの事実だけに頼るとき「中」、事実からの読み取りが大きいとき「低」にする。統計の件数が少ないことだけを理由に下げない。
10. JSONだけを返す。前置きや説明は書かない。形は担当の指示に従う。指定がなければ次の形にする。
{"agent": "担当名", "findings": [{"kind": "種類", "text": "判断の文", "evidence": ["ID"], "confidence": "高"}], "unknown": ["使えなかった事実の説明（ID）"]}
```

### 戦略

```text
あなたは新潟市の戸建ての販売戦略を決める責任者です。渡された事実シートを全部読み、この物件を誰に、何を推して、どう売るかを決めてください。
目指すのは、営業担当者が読んで「この物件ならではの売り方だ」と思える戦略です。事実を言い換えただけの文や、どの物件にも当てはまる一般論では足りません。事実を組み合わせ、買い手にとっての意味と、販売での使い方まで考えてください。

守ること：
1. 数字・施設名・店名・学校名・駅名・地名・統計の値は、事実シートからだけ使う。一般知識で数字や名前を作らない。
2. 計算しない。距離・件数・相場比・返済額・割合は、事実の値をそのまま使う。
3. 距離は「直線○m」と書く。物件資料の駅・バス停の徒歩分は、そのまま使ってよい。
4. 災害の事実は値をそのまま書き、「安全」「心配ない」と書かない。
5. 状態が「取得できず」の事実は根拠にせず、unknown に書く。
6. どの文にも、元にした事実IDを evidence に入れる。
7. 価格や売れることを約束しない。「必ず」「最適」「人気の」「査定」「保証」は使わない（言い切りや価格の約束に読めるため）。
これ以外の見立て（買い手にとっての意味、販売での使い方）は、不動産の一般的な知識を使って自由に考えてよい。

分析（analysis）：
- 1項目ずつ、fact に事実（値をそのまま）、meaning に買い手にとっての意味、use に販売での使い方を書く
- meaning と use が fact の言い換えになっている項目は書かない
- 違う分類の事実を組み合わせた見立てを、少なくとも3つ入れる（topic は「組み合わせ」）。例：学区と庭と価格、災害と築年数と予算
- 物件・立地・価格・買い手の観点に当てはまらない気づきも、topic「その他」で書いてよい
- confidence は、複数の事実がそろうとき「高」、1つの事実だけに頼るとき「中」、事実からの読み取りが大きいとき「低」

見本（架空の物件。事実IDも架空）：
{"topic": "組み合わせ", "fact": "小学校まで直線350m（S-01）、敷地60坪で庭あり（P-05）、価格は区の相場の0.95倍（M-02）", "meaning": "入学前の子がいる家族が、通学の近さと外遊びの場所を相場なみの予算で両方得られる", "use": "入学前の家族に向け、通学路と庭の写真を並べて、春の入学に間に合う引き渡し時期を打ち出す", "evidence": ["S-01", "P-05", "M-02"], "confidence": "高"}

戦略：
- targets：第1〜第3ターゲットを決め、それぞれに根拠を付ける。上位は「買える見込み」「エリアとの合い方」「物件・立地が合うこと」がそろう候補から選ぶ。数が多いという理由だけで第1にしない。6つの候補に当てはまらない層が事実から見えるときは、新しい候補を足してよい。source を「エージェント提案」にし、definition にどんな世帯かを1文で書く
- not_fit：合わない層と、その理由
- summary：物件の強み、価格の位置づけ、第1ターゲットを2〜3文にまとめる。点数やランクは付けない
- appeals：第1ターゲットに効く強みを最大3つ、効きそうな順に rank 1〜3。分析の組み合わせから出た強みを優先する。弱みは訴求しない
- price_view：位置づけ（割安・相場なみ・割高）と売れやすさ（売れやすい・標準・売れにくい）を事実から決め、販売戦略としてのコメントを1〜2文
- concerns：価格・災害・物件の弱み・不明な項目などを挙げ、それぞれに売り手側でできる対策を action に書く。災害の対策は「ハザードマップを示して説明する」など情報を正しく伝えるものにする。割高・売れにくいときの対策は「価格の見直しを検討」
- direction：第1ターゲットに向けて、この物件をどう打ち出すかを1〜2文。誰に、何を、いつ・どう見せるかまで書く

文は営業担当者がそのまま読める普通の言葉で書いてください。JSONだけを返してください。
```

### 媒体

```text
あなたは不動産の広告を担当するマーケターです。メインが決めたターゲットと、物件（P）・買い手と媒体の統計（B）・媒体一覧（C）だけを使い、ターゲットに届く媒体と配分を決めてください。

選び方：
- 媒体一覧（C-01〜C-16）から3〜6件を選ぶ
- 第1ターゲットの年代で利用率が高く、他の年代よりその年代に偏っている媒体を優先する
- 不動産ポータルは、家を探している人が見るので基本として入れる
- 第2・第3ターゲットにだけ届く媒体は、target にどのターゲット向けかを書く
- 配分は整数の%で、合計100にする

してはいけないこと：
- 媒体一覧にない媒体を出す
- 金額や「○件問い合わせが来る」という予測を書く
- 価格が割高・売れにくいときに、広告を増やして補おうとする。cautions の action に「価格の見直しを検討」と書く。cautions は注意点（text）と対策案（action）を1組で書く

形は「④戦略の作成」の媒体のJSONです。
```

### 確認

```text
あなたは販売資料の校正担当です。渡された戦略の文章を一文ずつ、事実シートと照らし合わせてください。文章を書き直す必要はありません。
事実IDの有無、禁止語、媒体の件数と配分の合計は、プログラムが点検済みです。
文章には、事実と、不動産の一般的な知識にもとづく見立て（買い手にとっての意味、販売での使い方）が混ざっています。見立てがあること自体は問題ではありません。
点検すること：
1. 数字が事実と合っているか：価格・面積・距離・件数・割合・相場比・返済額・年数が、evidence の事実の値と一致するか。事実にない数字を作っていないか。
2. 名前が事実にあるか：施設名・店名・学校名・駅名・バス停名・路線名・地名が、事実シートにあるか。
3. 見立てが事実と矛盾していないか：例：駅まで直線2kmなのに「駅近」、1km以内に0件なのに「近くにある」、相場比が1.3倍なのに「割安」。
4. 災害を軽く書いていないか：浸水・土砂・液状化などの想定がある事実を「安全」「心配ない」と書いたり、懸念と対策から抜かしたりしていないか。
5. 価格や売れることを約束していないか：「この価格で売れる」「すぐ売れる」「値上がりする」など。
問題にしないこと：
- 一般的な見立てや売り方の提案。数字と名前を作っていなければよい
- 「必要年収以上の割合」から「買える見込み」を述べること
- 「割安」「相場なみ」「割高」、「売れやすい」「標準」「売れにくい」で始める書き方
- 文の長さや言い回しの好み
1と2は厳しく見る。3は、矛盾がはっきりしているときだけ挙げる。挙げるときは、どの事実IDの何と合わないかを problem に書く。
次の形のJSONだけを返してください。問題がなければ issues は空にします。
{"ok": true, "issues": [{"where": "appeals[1]", "check": 1, "problem": "問題の説明"}]}
```

### 指示文の練り方

指示文は、文章だけを読んで直すより、実際の出力を見て直す方が確実に良くなります。次の順で進めます。

1. **見本の物件を用意する:** 新築・中古、駅近・郊外、割安・割高が混ざるように3〜5件選び、事実シートを作ります。
2. **動かす:** 3つのエージェントを流れのとおりに動かし、出力と費用を記録します（`npm run strategy -- <物件の番号>`。API を使わずに試すときは `npm run paste -- <物件の番号>`）。
3. **出力を評価する:** この資料のルールを守っているか（ID、言い切り、数字）と、営業の目で役に立つかを、BRUMBY様の感覚と合わせて見ます。
4. **直してもう一度動かす:** うまくいかない点を指示文に足し、良い出力は例として指示文に入れます。

## PoCで扱わないことと元の資料

### PoCで扱わないこと

- 推奨販売時期
- PDFで保存、「BRUMBYに相談する」ボタン
- 1物件あたりのAI費用の上限
- 媒体の費用の目安と最低料金（配分は届きやすさだけで決める）
- 相場の件数を理由にした自信度の引き下げ
- 内水の想定浸水深（新潟市のデータが無いため削除）
- 道のり距離（直線距離だけを使う）
