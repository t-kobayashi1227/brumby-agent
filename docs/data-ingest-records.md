# 公開データの取り込みの記録

PoCの確認1（公開データは足りるか）の材料として、取り込むたびの結果を残す。
件数・空欄の割合の詳細は、DBの `ingest_logs` にも記録されている。

### 実行したコマンドとAPI（復習用）

**1. 実行したコマンド**

```bash
npm run ingest -- reinfolib-transactions --pref 15 --from 2015Q1
```

| 部分 | 意味 |
|---|---|
| `npm run ingest` | `package.json` の `ingest` を動かす。中身は `tsx --env-file=.env.local scripts/ingest/index.ts` |
| `--` | ここから後ろを、npm ではなくスクリプトに渡すという区切り |
| `reinfolib-transactions` | 取り込むデータの名前（`scripts/ingest/jobs/reinfolib-transactions.ts`） |
| `--pref 15` | 都道府県コード。15＝新潟県 |
| `--from 2015Q1` | 2015年第1四半期から。`--to` を省くと、今の四半期（2026Q4）まで |

**2. コマンドの中で呼んでいるAPI**

四半期ごとに、次のAPIを1回ずつ呼ぶ（2015Q1〜2026Q4の48回）。

```
GET https://www.reinfolib.mlit.go.jp/ex-api/external/XIT001?year=2024&quarter=1&area=15
ヘッダー：Ocp-Apim-Subscription-Key: （REINFOLIB_API_KEY の値）
```

| パラメータ | 意味 |
|---|---|
| `year` | 取引の年（必須） |
| `quarter` | 四半期。1＝1〜3月、2＝4〜6月、3＝7〜9月、4＝10〜12月 |
| `area` | 都道府県コード |
| （`priceClassification`） | 今回は指定していない。省くと、取引価格情報と成約価格情報の両方が返る |

手で1回だけ試すときのコマンド（キーは自分のものに置き換える。`--compressed` は、gzipで圧縮された応答を戻すため）：

```bash
curl -H "Ocp-Apim-Subscription-Key: 発行されたAPIキー" --compressed \
  "https://www.reinfolib.mlit.go.jp/ex-api/external/XIT001?year=2024&quarter=1&area=15" > XIT001_2024Q1.json
```

応答（一部）：

```json
{
  "status": "OK",
  "data": [
    {
      "PriceCategory": "不動産取引価格情報",
      "Type": "宅地(土地)",
      "Municipality": "新潟市北区",
      "DistrictName": "葛塚",
      "TradePrice": "7000000",
      "Area": "120",
      "Period": "2024年第1四半期",
      "DistrictCode": "151010240"
    }
  ]
}
```

- まだ公表されていない四半期は、`404`（`{"message":"検索結果がありません。"}`）が返る。取り込みでは0件として扱う
- APIの説明：https://www.reinfolib.mlit.go.jp/help/apiManual/xit001/

**3. 取得したあとの流れ（`scripts/ingest/lib/runner.ts`）**

1. `dataset_versions` に版を作る（`loading`）
2. 四半期ごとにAPIを呼び、応答をそのまま Storage の `ingest-raw/reinfolib/XIT001/<版のID>/2024Q1.json` に保存する
3. 数字に直して `transactions` に読み込む
4. 件数と空欄の割合を数え、0件でなければ `active` に切り替えて、`ingest_logs` に記録する

**わかったこと**

- 林地（9地点）は価格の単位が「円/10a」。取り込みのときに1㎡あたりの価格の列へ入れてしまっていたので、処理を直した（**版7の林地の9地点は、`price_per_sqm` に円/10aの値が入ったまま**。直すかどうかは相談中）

### 実行したコマンドとAPI（復習用）

```
GET https://www.reinfolib.mlit.go.jp/ex-api/external/XPT002?response_format=geojson&z=13&x=7260&y=3162&year=2026
ヘッダー：Ocp-Apim-Subscription-Key: （REINFOLIB_API_KEY の値）
```

| パラメータ | 意味 |
|---|---|
| `response_format` | `geojson`（地図のデータの形式）。必須 |
| `z` / `x` / `y` | タイルの位置。`z` はズーム（13〜15）、`x`・`y` はそのズームでのマス目の番号（例の 7260/3162 は新潟市中央区の上近江・紫竹あたり） |
| `year` | 対象年（1995〜） |
| （`priceClassification`） | 今回は指定していない。省くと、地価公示（0）と地価調査（1）の両方が返る |

経度・緯度からタイルの番号を出す計算は `scripts/ingest/lib/tiles.ts`。タイルの位置は、国土地理院の「地理院地図タイル座標確認」（https://maps.gsi.go.jp/development/tileCoordCheck.html ）で地図から確かめられる。

## 町丁目の境界（e-Stat 国勢調査2020 小地域）

| 項目 | 内容 |
|---|---|
| 取り込んだ日 | 2026-10-03 |
| コマンド | `npm run ingest -- estat-boundaries --pref 15` |
| 版 | 版13（`dataset_versions.id = 13`、active） |
| 範囲 | 新潟県（`pref:15`） |
| 件数 | 7,703件（町丁目 7,697、水面など 6）。元の図形は8,114個で、飛び地をKEY_CODEごとに1つにまとめた |
| かかった時間 | 約1分 |
| 容量 | `areas` 18MB（DB全体 132MB） |

### 取得のしかた
- APIではなく、統計GISのダウンロード（Shapefile、世界測地系（JGD2011）の緯度経度、属性はShift_JIS）。APIキーは要らない
- URL：`https://www.e-stat.go.jp/gis/statmap-search/data?dlserveyId=A002005212020&code=15&coordSys=1&format=shape&downloadType=5&datum=2011`
- zipのまま Storage の `ingest-raw/estat/census2020_boundary/<版のID>/r2ka15.zip` に保存する

### 確かめたこと
- 図形はすべて有効（`ST_IsValid`）で、空のものはない
- 面積の合計は12,692km²（水面を含む）。新潟県の面積（約12,584km²）とほぼ合う

### 取り込みの経過
| 版 | 結果 | 内容 |
|---|---|---|
| 版12 | 失敗 → 削除 | SQLの関数名の誤り（`json_to_recordset` → `jsonb_to_recordset`）。直して取り直した。0件だったので、Storageの生データとあわせて削除した |
| 版13 | 成功（active） | 上の結果 |
